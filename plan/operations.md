# 葬祭ビジネス定点 定期運用の手順

関連: [[CLAUDE]] / [[log]]

定期タスク `sosai-teiten-monthly` は、このファイルの手順で動く。毎月10日と25日の13時ごろ（Claude アプリが起動しているとき。閉じていれば次に起動したとき）。1回の実行で公開する記事は1本まで。

## 0. 前提
- 作業場所: `C:\Users\Administrator\Projects\play\sosai-teiten`。コマンドは `python -X utf8` で実行する。
- `CLAUDE.md`（とくに「記事の基準」「データ源と利用条件」）、このファイル、`plan/log.md` の最後の数件を読む。
- `git status` で前回の作業の残りがないかを見る。`git pull` で最新にする。

## 1. 新しい月報が出ているかを確かめる
1. `data/deaths_monthly.csv` の最後の月を見て、その次の月を「次に待つ月」とする。
2. 厚生労働省「人口動態統計月報（概数）」の個別ページ（HTML）を WebFetch（または web-fetch エージェント）で開く。URL の形は `https://www.mhlw.go.jp/toukei/saikin/hw/jinkou/geppo/m<西暦>/<2桁の月>.html`（例: 令和8年6月分は `m2026/06.html`）。一覧フォルダは 403 なので使わない。
3. ページがまだない（404 など）ときは、新しい月報は未公表。手順4で「未公表」と記録して終える。

## 2. 数字を手に入れる（ダウンロードはしない）
- **PDF・Excel などのファイルのダウンロードはしない。** ユーザーの許可が要り、定期実行では許可を取れないため。
- HTML のページ本文に、記事に必要な数字（その月の死亡数、前年同月の死亡数など）が書かれていれば、それを使ってよい。写した数字は `data/deaths_monthly.csv` の書式に合わせて追記し、`python -X utf8 data/verify_deaths.py` を通す（検算が通らなければ記事にしない）。
- 数字がファイルの中にしかないときは、記事を作らない。手順4で、許可が要るファイルの URL・名前・大きさ（ページに書かれていれば）を記録し、完了報告の最初に「このファイルのダウンロードを許可してもらえれば記事にできる」と書いて終える。

## 3. 書いて公開する（数字が手に入ったときだけ）
1. `CLAUDE.md` の「記事の基準」に従う。数字は `python -X utf8 data/figures.py` で算出したものを写す（手で打たない）。本文は3,000〜8,000字。しずかの文体（静かに丁寧に。感嘆符・あおる表現なし）。既存の記事 `site/content/2026-11-24-deaths-2026-h1.md` を手本にする。
2. 出典（厚生労働省の公共データ利用規約に沿った出典の記載と、加工した旨）を記事に書く。東京都の資料は、表やグラフを複写せず、数字を自分の言葉で書き、リンクはトップページだけ。
3. yomiyasu で推敲・検査する（`tools/export_text.py` で文章を取り出し、`yomiyasu_check.py run --material ... --final ... --doc-type article --stance 説明 --fact-gaps` → `verify`）。
4. site フォルダで `python -X utf8 check.py` がエラー0件、`python -X utf8 build.py` が通ること。すべて通ったら公開する。通らなければ `draft: true` のまま残し、理由を記録する。

## 4. 記録と push
1. `plan/log.md` に、日付・結果（公開／未公表／ファイルの許可待ち）・記事やファイルの URL を1〜3行で追記する。
2. `git config --local user.email` が `...@users.noreply.github.com` であることを確かめてから、`git add -A` → `git commit`（「何を・なぜ」を1行）→ `git push`。
3. 公開した記事は、push から数分おいて https://pocketlog-note.github.io/sosai-teiten/ で表示を確かめる。
4. 完了報告は「何をしたか／確認できたこと／未確認のこと」に分ける。ユーザーの許可が要るものがあれば最初に書く。

## やってはいけないこと
- ファイルのダウンロード、`mockup/` の架空の数字を使うこと、出典のない数字を書くこと。
- 東京都の資料の表・グラフの複写、個別ページへのリンク。
- アカウント作成、X など外部への投稿（X は `site/x-drafts/` の下書きまで）。
- 1回の実行で2本以上公開すること。`git push --force` と履歴の書き換え。個人のメールアドレス・本名を出すこと。
