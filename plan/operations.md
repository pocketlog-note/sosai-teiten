# 葬祭ビジネス定点 定期運用の手順

関連: [[CLAUDE]] / [[log]]

定期タスク `sosai-teiten-monthly` は、このファイルの手順で動く。毎月10日と25日の13時ごろ（Claude アプリが起動しているとき。閉じていれば次に起動したとき）。1回の実行で公開する記事は1本まで。月報（概数）は毎月、月の初めごろ（4日〜8日ごろ）に公表されるので、10日の実行で拾えることが多い。

## ユーザーの許可（ファイルのダウンロード）
- **状態: 未取得**（2026-11-25 にユーザーへ依頼中。許可が出たら、この行を「許可あり（日付）」に書き換える）
- 許可を求めている内容: 厚生労働省の月報（概数）の「当月分を含む過去1年間の動向」の Excel（約24KB）を、毎月1回、定期タスクが `data/raw/`（git管理外）に保存して読んでよい。厚生労働省のサイトの、この1ファイルだけ。
- **状態が「許可あり」でない限り、`--allow-download` を付けない。** 付けないときは、Excel の URL と名前を記録し、完了報告の最初に許可の依頼を書いて終える。

## 0. 前提
- 作業場所: `C:\Users\Administrator\Projects\play\sosai-teiten`。コマンドは `python -X utf8` で実行する。
- `CLAUDE.md`（とくに「記事の基準」「データ源と利用条件」）、このファイル、`plan/log.md` の最後の数件を読む。
- `git status` で前回の作業の残りがないかを見る。`git pull` で最新にする。

## 1. 新しい月報が出ているかを確かめて、数字を取り込む
プロジェクトのルートで:
1. 許可があるとき: `python -X utf8 data/fetch_month.py --allow-download`
   許可がないとき: `python -X utf8 data/fetch_month.py`（保存しない）
2. 終了コードで分ける。
   - 3（まだ公表されていない）: 「未公表」と記録して終える。続けて何度も取りに行かない。
   - 4（許可が要る）: 出力の `PUB_DATE`（公表日）と `Excel:`（URL）を記録し、許可の依頼を完了報告の最初に書いて終える。
   - 5（想定外）: 出力を記録して終える（ページの構成や Excel の行の位置が変わった可能性。人が確認する）。数字を推測で補わない。
   - 0（取り込み完了）: 出力の `PUB_DATE=` を控えて手順2へ。
3. 取り込みの仕組み: Excel の「過去1年間の合計」の増減に前年同月の死亡数を足して、新しい月の死亡数を `data/deaths_monthly.csv` に追記する（2026年1〜6月で、月報の第2表の値と完全に一致することを確認済み）。取り込み後に `data/verify_deaths.py` の検算が自動で走る。検算が通らないときは記事にしない。
- 保存済みの過去1年間の合計と食い違うと、取り込まずに止まる（終了コード5）。数字が改訂された可能性があるので、人が確認する。
- PDF など、Excel 以外のファイルはダウンロードしない。

## 2. 下書きを作る
site フォルダで: `python -X utf8 draft_month.py <年> <月> --pub <PUB_DATE>`
- 例: `python -X utf8 draft_month.py 2026 7 --pub 2026-12-08`
- 数字・表・グラフ・ファクト欄・集計方法は自動で埋まる。次の2か所だけ【要確認】が残る。
  1. 「今月の火葬・葬祭の動き」の節（とファクト欄・集計方法の対応する箇所）
  2. しずかの見解
- 1月分（`<年> 1`）は作れない。手で書く（既存の記事を手本にする）。

## 3. 【要確認】を埋める
1. 「今月の火葬・葬祭の動き」: 公的な資料（自治体・国の公表資料）で確かめた新しい動きだけを、出典つきで2〜3段落。WebSearch・WebFetch で調べる。東京都保健医療局の資料は、表やグラフを複写せず、数字を自分の言葉で書き、リンクはトップページだけ。新しい動きが確かめられないときは、節とファクト欄の対応する項目ごと削除する（本文は自動の部分だけで3,000字を超える）。過去の月の記事の節と同じ内容を繰り返さない。
2. しずかの見解を2段落。静かで丁寧な文体、「わたし」を使ってよい、感嘆符・不安をあおる表現・冗談は使わない、死を軽く扱わない。ファクトにない数字は書かない。個別の事業者を評価しない。
3. 数字を手で直さない。直したいときは `data/` の値を直してから `draft_month.py --force` で作り直す。

## 4. 推敲・点検・公開
1. yomiyasu で推敲・検査する。`python -X utf8 tools/export_text.py site/content/<記事>.md _text/<名前>-final.md` で文章を取り出し、資料ファイル（`_text/<名前>-material.md`。月報の数字、`python -X utf8 data/figures.py` の出力、今月の動きの根拠を書く）と一緒に `yomiyasu_check.py run --material ... --final ... --doc-type article --stance 説明 --fact-gaps` → `verify`。
2. 公開前に、記事の中の数字どうしの整合を目で確かめる（差を書いているときは、表示している数字どうしで引き算する）。
3. site フォルダで `python -X utf8 check.py` がエラー0件（本文は3,000〜8,000字）、`python -X utf8 build.py` が通ること。すべて通ったら公開する。通らなければ `draft: true` を足して残し、理由を記録する。

## 5. 記録と push
1. `plan/log.md` に、日付・結果（公開／未公表／許可待ち）・記事やファイルの URL を1〜3行で追記する。
2. `git config --local user.email` が `...@users.noreply.github.com` であることを確かめてから、`git add -A` → `git commit`（「何を・なぜ」を1行）→ `git push`。
3. 公開した記事は、push から数分おいて https://pocketlog-note.github.io/sosai-teiten/ で表示を確かめる。
4. 完了報告は「何をしたか／確認できたこと／未確認のこと」に分ける。ユーザーの許可が要るものがあれば最初に書く。

## やってはいけないこと
- 許可の状態が「許可あり」でないときの、ファイルのダウンロード。許可の範囲（上記の Excel 1ファイル）を超えるダウンロード。
- `mockup/` の架空の数字を使うこと、出典のない数字を書くこと、数字を推測で補うこと。
- 東京都の資料の表・グラフの複写、個別ページへのリンク。
- 厚生労働省のサイトへ、1回の実行で何度もアクセスすること（`fetch_month.py` は1回まで）。
- アカウント作成、X など外部への投稿（X は `site/x-drafts/` の下書きまで）。
- 1回の実行で2本以上公開すること。`git push --force` と履歴の書き換え。個人のメールアドレス・本名を出すこと。
